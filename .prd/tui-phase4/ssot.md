## What "그대로" means here

The oracle is the **running fx binary at `c1db919`**, side by side with xfx in the same terminal size, not a reading of fx's source. Source is read to find the rule behind what the screen shows. Every UI round closes on a fx↔xfx capture pair taken on an isolated tmux socket.

The first capture (120×40 and 80×24, isolated `HOME`, fake key) established the frame architecture:

## Deliberate xfx divergences this workstream reverses

Recorded so the weekly review sees them; "그대로" authorizes each.

1. Opt-in `XFX_TUI=1` → the TUI is the default on a terminal; pipes and subcommands keep the line shell/commands.
2. A band anchored to the last row → fx's floating footer.
3. The `───` divider and `> ` prompt → fx's blank dividers, `┃ ` composer and hint row.
4. The 7-row slash list → fx's filterable menu.
5. `/help` as transcript text → fx's help menu.
6. `/clear` as "clear the screen, keep the conversation" → fx's "start a fresh conversation while keeping managed processes" (`app_commands.zig:667`).
7. Approval keys: xfx's Esc = deny / Ctrl-C = interrupt the turn → fx's Esc = cancel the turn / Ctrl-C = deny this call (`app_input_runtime.zig:3139-3143`, `src/ui/input/runtime.zig:61`, pinned by fx `tests/e2e/tui-permissions.test.ts:1099`). The model's own questions (`ask_user_question`) likewise: xfx's Esc = decline the question, the model told so with the sentinel `(user cancelled the question)` and the turn going on → fx's Esc at an empty field = cancel the turn (`app_input_runtime.zig:3137` → `cancelQuestionPrompt`, `input_question_runtime.zig:59-83`), and Ctrl-C = the same (`src/ui/input/runtime.zig:138` `3 => .cancel` → `question_prompt.zig:327`); the call answers `aborted by user` (`session.zig:64`) and the model never receives the sentinel (fx e2e `tui-decision-prompts.test.ts:2454`). Esc at a freeform answer with text in it arms a clear instead (`app_input_runtime.zig:3120-3135`).
8. Ctrl-P: xfx's history-previous → fx's model catalog (`escape_parser.zig:271`); history stays on Up/Down as in fx.
9. Slash lines are not echoed into the transcript, commands with no argument match exactly, and anything else is `✗ command: Unknown command. Try /help.` (fx `input_submit_runtime.zig:707-717`, `command_router.zig:121-133`).

## Tensions

- **The Gateway's model catalog without a credential.** fx falls back to the public catalog when it has no key (`fetchWithPublicFallback`, `model_catalog.zig`; the menu then says `Using the public model catalog; sign in or use an API key for team-private models.`). xfx asks for no catalog without a key (`provider::model::catalog_for` answers `None`): it does not contact a remote host on its own initiative, and a Gateway session with no credential cannot run a turn either, so `/model` there lists nothing (`No models available.`) and applies an id as typed. Kept: the fallback would buy a list of models the session cannot use, for an unsolicited request to a remote host.
- **The model catalog is read when something needs it, not at launch.** fx preloads its catalog when the session starts (`model_cache_runtime.zig`), so its footer settles on whether the model in force takes the session's effort within a second. xfx reads the catalog when `/model`, its column or a turn with a non-default effort first needs it (a launch makes no network call; a provider switch reads the new provider's at once, as fx's switch adopts the target's, `app_auth_runtime.zig:1377`), so until then the footer shows the effort the way fx's does while its catalog is loading (`active_capabilities_pending`), and a typed `/model <word>` before any read is resolved -- and announced -- by the runtime rather than at once.
- **The catalog load is work, not control.** Opening `/model`'s column or menu mid-turn asks the runtime for a catalog it has not read; the runtime reads it after the turn (it is one socket, on the thread that owns the turn), so the column says `loading models...` until then. A model change itself is a control message and is never held up this way.
- **`/fast` and `/ultrafast on` before any catalog is read are answered when it arrives.** fx decides them at once against the catalog it preloaded. xfx's band decides them against the catalog row of the model in force, and with none read it holds the command, asks for the catalog and answers -- in the order given -- the moment it arrives (or says there is no mode when it cannot be read). With a turn running the read waits behind the turn (the entry above), so the answer does too. `/fast` while Fast is on, `/ultrafast off` and `/ultrafast status` need no row and are answered at once, unless an earlier one is held.
- **The speed column is the TUI's, and the Gateway's.** The line-oriented shell sends neither an effort nor a speed (it never did send an effort), so its `/fast` and `/ultrafast` say so instead of switching. llmux reads no per-request speed -- its Fast is the daemon's own codex setting (`2lab-ai/llmux src/config/schema.rs:545-550`, `src/provider/codex.rs:422-437`) and its catalog publishes no speed -- so no llmux row offers one: the column never opens there, `/fast` says the model has no fast mode, and nothing is sent.
- **A turn in Ultra that cannot be sent in it is refused in xfx's words.** fx refuses it too (`resolveUltrafastProviderOptions`, `model_capabilities.zig:209-224`: no silent downgrade) with an error name and no sentence of its own; xfx's turn fails with `Ultra mode is unavailable for this model; run /ultrafast off or choose a model that offers it`.
- **A model change put aside while `/provider` switched** is saved for the provider it was chosen under and lands on no selector of the new one, with a warning (`saved for <old>; the provider changed to <new> before it could be applied`); one the band never resolved is dropped with a warning. fx cannot reach this state -- it refuses the switch while work runs -- and its end state for the same keystrokes is the same model saved under the old provider. A model saved under the provider in force writes `provider` beside it, as fx's patch does (`session_commands.zig:894-896`, `:1180-1181`); this one does not, which would write the old provider back over the switch.
- **A speed change is said once its save has answered.** fx persists before it announces (`applyFastMode`, `session_commands.zig:781-797`; `applyUltrafastMode`, `:839-859`), on the thread that ran the command, so its report -- `saved to user settings (scope=user); fresh sessions here use higher-precedence model=process_override`, or the failure -- is the line above `* fast: on`. xfx keeps that order without writing on the UI thread: the band writes the save on a writer thread of its own (`src/tui/speed_save.rs`, one thread so two saves land in the order given) and holds the announcement in the document queue until the write answers -- milliseconds -- with everything after it behind it: notices, typed-command errors and the answer's stream (`Mark::Saving`). The switch is in force, on the footer and sent to the runtime at once. The runtime writes the same switches again when it applies them, silently: it writes model changes, and one put aside behind a turn is saved when the turn ends with the switches it turned off, so a `/fast` typed after it has to land after it. `/model` keeps its order: fx announces a model selection before it persists it (`selectModelFromPicker`, `session_commands.zig:913-914`; `setResolvedModel`, `:1172-1188`), so a model save's report is the line under `Switched to`, as xfx's is.
- **Operational lines wrap as xfx's prose does, and fx's prose keeps no word alone on its last row.** The two lines fx writes as operational text -- the unconfirmed-Ultra line (`orchestrator.zig:8015-8022`) and the Fast-unavailable line (`:7253-7262`) -- are xfx's too, in the answer ahead of the line the presenter holds. At 120 columns the Ultra line is one word short of fx's break: fx's assistant wrap moves the word before an overflowing final word down with it (`assistant_wrap.zig:219-267`, `:269-298`, `isFinalWordOnLine` `:862-883`), so its rows end `… a standard or` / `lower tier.`; `tui::wrap::wrap` breaks at the first word that does not fit (`… a standard or lower` / `tier.`). The rule is fx's for every assistant row, not for these lines; it is recorded for the prose wrap rather than special-cased here.
- **`⚡︎` is two cells.** fx counts the sign and its text-presentation selector as the sign's own width (`display_width.zig:251-256`, `:697`) and so does the terminal; the width table xfx's painter used counted one. `tui::wrap`'s measure now follows fx's rule for any base with U+FE0E, so the hint row's budget and the grid agree with what is painted.

- `UPSTREAM.md` pins `580a0c5`; this workstream cites `c1db919` for every UI claim. The pin advances to `c1db919` for the UI ledger in this workstream rather than leaving two revisions implicit.
- **Resize.** fx re-solves and repaints the frame it owns after a resize (`resize_runtime.zig`, `frame_layout.solveWithPreservedRowRelease`). xfx pins its band to the bottom of the resized screen instead of floating it (`Shell::resize` sets the document past any screen): the rows above the band are the terminal's own document after a reflow, and xfx has no way to know where a terminal put them, so a band floated under a guess would paint over them. The next document row xfx writes lands on the row above the band, and from then on the document is counted as ending there (`commit_frame` counts what an append leaves **on** the screen, not what it scrolled off), so a band that shrinks afterwards keeps its top row and leaves the rows it gave back blank under the hint, as a floating band does -- it never moves up onto a row it did not hold. Captures at a fixed size match; a resize capture differs by where the band sits until the screen has filled.
- **Partial lines while streaming.** fx shows an answer's line once the markdown presenter has its end (captured mid-stream: only the activity row is visible). xfx does the same since 3efe232; xfx's earlier per-character pacing of partial lines is gone with it.
- **Tool backend is not UI.** xfx's `edit_file` refuses a file the session has not read (`src/tools/mutate.rs:547`); fx edits directly. That is a safety rule of xfx's tool layer, not a screen, so this workstream keeps it; paired captures of an edit without a prior read diverge for that reason and the receipts say so.
- **A provider switch keeps the conversation, and says once what it could not carry.** fx's `/provider` swaps the selection and leaves the session alone (`app_auth_runtime.zig:1377-1381`); its encoders send a message's replay state only to the provider and model that produced it and drop it otherwise, with a debug trace and nothing on the screen (`projectProviderReplay`, `types.zig:1548-1563`; `provider_replay_omitted`, `builtins/gateway.zig:183-185`). xfx keeps the conversation too (P1) and drops the same way -- keyed by wire, where fx keys by provider **and model**, so a `/model` change on llmux still replays the blocks its daemon signed -- but its own rule is that a drop is never silent (`.prd/04-providers.md` §Provenance), so the first request after a switch off llmux says `! session: this session recorded reasoning on the anthropic_messages wire and is continuing on vercel_gateway, so that reasoning was not carried over`, once for the conversation (`Conversation::unsaid`; the image read-back notices are said once the same way). Kept: one warning row fx does not print, for a model told less than the log holds.
- **A resume continues on the provider in force.** fx's resume restores the provider and model the session last recorded (`restoreRuntimePreferences`, `app_session_runtime.zig:6126-6175`, `replaceSelection` at `:6147`); xfx's resumes on the configured provider and writes the switch into the log when it differs (`Runtime::resume`). After a `/provider` the two agree, because the switch wrote the profile (`receipts/p1`, `resumed`); they part only when the profile changed after the session did.
- **The window title on exit.** fx clears it (`ESC]2;BEL`; an empty pane title after `/quit`). xfx clears it and then pops the title it pushed at launch (`term::RESTORE`), so a terminal with a title stack gets the user's own title back and one without ends cleared, as fx's does. Kept: giving back what was borrowed is restore hygiene, not a screen this workstream copies.

Kept: the second route is a second model, a tool xfx does not advertise (`vision` is deferred in `docs/parity.md`) and a forced tool call that fails the turn when the model will not make it (`RequiredVisionToolCallMissing`, `fx-image-nonnative-40x120-sent`). llmux's catalog has no capability field, so there the image is sent and the daemon's 400 is the answer.

- **The `@` file picker: what is left as it is.** Each of these is a difference from fx (`c1db919`) that this workstream records rather than closes:
  - *The prompt text is trimmed.* A chosen file ends `@path ` with a space, which fx sends as typed (`"text":"@docs/guide.md "`); xfx trims every prompt it sends (`src/interactive.rs` `classify`), so the request carries `@docs/guide.md`. Not a screen; the receipts show it in the request bodies (`receipts/e1/README.md`).
  - *No on-disk index cache.* fx paints a warm index from `<home>/.fx/file-index/` (`file_index_cache.zig:3`) before discovery and saves one after (`file_index.zig:803-821`, `:829-832`; `file_index_cache.zig:66`, `:141`). xfx discovers every time and keeps the index in memory only; its first index is searched as it is published, as fx's is, but it is never painted from a previous process's walk.
  - *One index root.* fx indexes the primary directory and every active additional directory (`activeRootsAlloc`, `file_index.zig:857-876`). xfx indexes the workspace only; extra roots come with `/workspace`.
  - *No `$` skills picker.* fx opens an inline skills list on a `$` word at the end of the draft (`findInlineSkillQuery`, `picker_state.zig:524-541`). xfx has no skills, so `$` is a character until `/skills`.
- **Interrupting a running command** (closed by F4, `9157003`). fx kills a running shell command on Ctrl-C at once. xfx's tool holds the runtime thread, so the control message is read only after it returns (`src/tui/worker.rs` `raced_against_control`); the UI now raises the running turn's own flag with every stopping message (`WorkHandle::control`), which the command's supervisor polls every 10 ms (`src/tools/terminal.rs` `supervise`), so the command and its group are killed at the keystroke and answer fx's `aborted by user`. A file tool does not poll the flag and still runs to its end before the stop is read; its row shows its real result.
- **The retry budget is xfx's, not fx's.** fx keeps a turn alive through transient failure for up to ten attempts and fifteen minutes (`default_max_provider_attempts: usize = 10`, `model_response_recovery.zig:3`; the budget, `:7-9`) and backs off about a second, growing. xfx spends at most three attempts on a step (`gateway::DEFAULT_MAX_ATTEMPTS`), 250 ms then 500 ms (`agent::machine::retry_delay`). Retry policy is not UI and is kept: the row, its countdown, `✓ recovered · attempt N` and the `recovery:` records are fx's; the numbers in them (`attempt: n/3`, no `in 1s` for a wait under a second) are xfx's policy.
- **Escape does not pause a recovery.** fx's Escape pauses only its unbudgeted wait for connectivity (`pauseActiveRecovery`, `input_interrupt_runtime.zig`: `isConnectivityWaitActive`, set only for `waiting_for_connectivity`, `worker_runtime.zig:884-888`; chosen only for `connectivity_lost`, `model_response_recovery.zig:166-180`), and the pause persists a recovery checkpoint the session resumes from (`orchestrator.zig:7023-7040`, `finishRecoveryPaused` `:5075-5105`). xfx retries a lost connection within its three attempts and has no checkpoint, so there is no wait for Escape to pause; over every retry xfx makes, fx's Escape arms the interrupt (`app_input_runtime.zig:3163-3176`), and xfx's does the same.
- **A refusal's words.** A refused call now goes as fx's `execution-denied` with the refusal as its reason (`vercel_protocol.zig:742-744`); the words are xfx's (`write_file was not permitted: …`) where fx's are a JSON error object (`{"error":{"type":"tool_permission_denied",…}}`, `tool_result_errors.zig:289-320`). The llmux path has no denial of its own and keeps `is_error` (`2lab-ai/llmux src/provider/responses_request.rs:1148-1151`).
- **Generated session titles (W9): what is left as it is.** fx asks its provider for a session title after a fresh session's first prompt and installs it as the session's title (`session_title_generation.zig`, `app_session_runtime.zig:3659-3779`); W9 ports the request, the answer's cleaning, the gate, the `/settings` row (`settings_catalog.zig:272`), the install rule -- against the one derived title every listing reads, D1's port of fx's (`DurableState::derived_title` over `title_of`, `session_display_metadata.zig:33-147`) -- and `/trace`'s `## Session Title`. - **`/settings` · Collapse tool calls switched off does not expand the groups on the screen.** fx re-renders the visible transcript both ways (`markTranscriptStructureDirty`, `app_commands.zig:4120-4133`). xfx re-projects the rows it wrote and can still describe: switched **on**, each group on the screen loses its call rows and cancelled lines where they stand -- a group whose header has already left the top of the screen too -- and the rows under them move up (`Band::collapse_groups`, read off the rows' recorded kinds; no scroll, nothing made up), as fx's does (`receipts/d4d/*-settings-collapse-40x120-collapse-on`); the group the turn is still writing is rewritten as its header and gives the rows it lost back, so what comes next lands under its blank row (`*-settings-collapse-open-*`). Switched **off**, only the open group is drawn again expanded: a group written collapsed never had its call rows on the screen, and the band holds no closed group's calls to put back -- a closed group is the terminal's document. And rows in scrollback are never touched: where fx re-renders a full screen and pulls older rows down into the space a collapse frees, xfx's top rows stay where they are and the freed rows are the band's (`*-settings-collapse-open-40x120-after-esc`: the same rows one row lower).
- **`/undo`: what is left as it is.** W6 ports fx's file-op journal (`ChangeTracker`, `src/core/workspace/change_tracker.zig:30-99`) in memory, as fx's is; three differences are deliberate (a fourth, the journal left behind by a provider switch, closed with P1: the switch keeps the conversation and its journal, as fx's `/provider` keeps its tracker, `runProviderCommand`, `app_auth_runtime.zig:387`):
  - *The read-proof rule holds for an undo.* fx puts the preimage back over whatever is at the path (`undoLast` → `restoreContent` → `writeFileAtomic`, `change_tracker.zig:53-81`, `:91-93`), and its own test replaces a symbolic link standing there with the preimage (`:501-537`). xfx holds an undo to the rule every one of its writes obeys: the file must still be what the change left there, or what the session last read, so a file edited by someone else since, or a link at the name, is `Could not undo <path>` and left as it is (`src/tools/mutate.rs` `take_back`). The change is spent either way, as fx spends it (`:53-57`).
  - *A byte bound beside the count.* fx keeps 100 entries whatever their size (`max_stack_size`, `change_tracker.zig:33`; `pushOperation`, `:45-51`). A preimage is a whole file of up to 10 MiB here (`ToolLimits::max_read_bytes`), so xfx also drops the oldest past 64 MiB of preimage, always keeping the newest (`src/tools/undo.rs` `MAX_TRACKED_BYTES`).
  - *Mid-turn, the undo waits for the turn but is pinned to the keystroke.* fx runs `commandUndoLast` from its command handler at once whatever the worker is doing (`app_commands.zig:366-392`, `:1242-1290`). xfx's runtime thread does it once the running work has said its last word, never between one call's commit and the next call's read; the band sends the journal's position at the keystroke (`tools::undo::Mark`), so the change taken back is the one newest then, as fx's is, and a later change to the same file makes it `Could not undo` rather than a restore that discards that change. What differs from fx is only when the notice appears and the file changes: at the turn's end, not at the keystroke.
