## fx's count, read at the pin

fx counts a line a display unit at a time (`displayUnitAt`,
`src/core/shared/display_width.zig:234-263@481104fd`): an ASCII byte; an
RGI emoji sequence whole, two cells (`:246-247`); a variation base and its
U+FE0E (its own width) or U+FE0F (two cells, `:251-260`); else one code
point, `runeWidth` (`:275-282`):

- 0 for NUL, C0 and C1 (`:276-277`);
- 0 for a zero-width continuation (`isZeroWidthContinuation`, `:409-420`):
  `isCombining` (`:400-407`: U+0300-036F, U+1AB0-1AFF, U+1DC0-1DFF,
  U+20D0-20FF, U+FE20-FE2F, U+FE00-FE0F), the skin-tone modifiers
  (`emoji_modifier_ranges`, `unicode_display_data.zig:250-252@481104fd`),
  U+200B-200F, U+202A-202E, U+2060-206F, U+FEFF, U+E0001-E007F,
  U+E0100-E01EF;
- 2 for `wide_ranges` (`unicode_display_data.zig:40-164`, U+302E in
  `0x2FF0-0x303E` at `:81`) or `emoji_presentation_ranges` (`:166-248`, the
  regional indicators `0x1F1E6-0x1F1FF` at `:204`);
- 1 for everything else.

fx's grid takes each unit at that width (`engine.zig:1187-1191@481104fd`)
and joins a unit of no cells to the cell before it (`:1193-1197`). Neither
file moved between `c1db9191` and `481104fd` but for `decodeUtf8Sequence`
(malformed UTF-8 only); `unicode_display_data.zig` is the same bytes.

`fx_rune_width.py` reads the four range tables out of
`unicode_display_data.zig@481104fd` itself and applies `runeWidth`: fx's
count of every scalar, independent of xfx's port
(`src/markdown/display_width.rs`).

## Part 1: the scalars fx counts wider -- copied

`wrap::width` (`src/tui/wrap.rs:108`), a grapheme cluster at a time
(`painting`, unicode-segmentation 1.13.3), each cluster `cluster_cells`: the
width table's (unicode-width 0.2.2) string width, but for a cluster holding
one of WIDTH-DISPUTED's 14, counted by upstream's rule. A vowel sign,
U+302E, U+FF9E join the character before them in a cluster (Extend) and
U+0605 the one after it (Prepend), and the table gives the cluster the
base's width: the mark takes none. fx counts each on its own.

`ok`: every glyph of the text, in order (a `\u{NNNN}` token reads as the
glyph it names); a cell the terminal draws as nothing is not asked for. The
rows themselves, each side, are in `measure.txt`; the screens in `fx/`,
`red/`, `xfx/` (tmux) and `ghostty/` (libghostty-vt).

Three mechanisms, per terminal:
- **shift**: a scalar drawn wider than counted moves every cell after it
  right of where the frame holds it (U+261D, U+1F590, U+E0002 on tmux;
  U+2E3A on libghostty-vt);
- **past the margin**: a row the count ends at the margin is drawn wider,
  and its tail is written into the last cell or not at all (line 3's U+261D
  dropped on tmux, U+2E3A on libghostty-vt; four U+261D in front: `TAIw`,
  the `L` and three `w` lost);
- **overwrite**: the anchor fx writes after the next glyph with a variation
  selector (`ESC[{col}G`, `engine.zig:2586-2588@481104fd`; xfx's since
  ENGINE-VS-ANCHOR, `src/tui/grid.rs`'s `put_unit`) moves the cursor *back*
  over glyphs a shift already drew, and the glyphs after it overwrite them:
  `fam ☝ ⸺ 🖐 x` U+E0002 `y a` U+FE0F `b` reads `… x󠀂b  c` on tmux (`y a`
  lost) and `… xy b` on libghostty-vt (`a` lost). Only on rows a frame
  writes (Ctrl-O, the composer, fx's live answer); xfx's answer rows are the
  document's, written as they stand (`frame.rs`'s `place`).

fx has every one of them, on every surface; the base's xfx had them cell
for cell but on the answer's short row, which it wrote as the document's.

**The decision, by surface:**
- **Ctrl-O, a file's or a tool's line** (diff rows, a call's argument,
  result and output): named, `\u{261d}` (`drawn_wider_named`,
  `src/tui/full_transcript.rs:2596`), as the review names them
  (`approval_view`'s `tamed`): an emoji base with its U+FE0F, a U+FE0F after
  one, a flag and a keycap stay; a scalar of no cells right after a tab,
  which the row's walker draws nowhere, stays as fx's does. Unsafe to copy:
  the text is a file's or a tool's, the person reads it as the record of a
  change, and copied it does not read as the file holds it (above). The
  ledger's `ctrl-o-drawn-wider-named`.
- **The inline transcript and the composer:** fx's bytes, measured as fx's
  defect (docs/parity.md, the full-screen TUI row). An answer is the model's
  own words and a draft the user's own, so neither shows text a file or a
  tool put there, and xfx's answer rows overwrite nothing; naming would show
  `\u{261d}` for a text-style emoji in prose and in the draft being edited.
  The one row xfx and fx differ on, the answer's short row, is fx's
  overwrite that xfx's document row does not copy: the ledger's
  `inline-band-row-anchor`.
- **Ctrl-O's answer rows** (Response) are the model's, written as fx
  writes them, as inline.

**What starts showing as a token, where fx shows the glyph:** in a file's or
a tool's line on Ctrl-O, ☝ ⛹ ✌ ✍ 🏋 🏌 🕴 🕵 🖐 without their U+FE0F (with it
they stay), the two- and three-em dashes ⸺ ⸻, U+FE0F after a character that
takes no emoji presentation (a letter, a space, a soft hyphen), and the tags
U+E0002-E001F; in the review, the 417 regional-indicator pairs that are no
flag (part 1).

Tests (`src/tui/full_transcript.rs`):
`a_character_a_terminal_draws_wider_than_it_is_counted_is_named_in_a_files_line`
-- line 2 through the diff rows' and the details' spelling, what stays, the
