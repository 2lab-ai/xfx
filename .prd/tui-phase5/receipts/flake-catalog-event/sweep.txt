# Class sweep (line numbers at this branch's fix commit, src/tui/worker.rs unless named)

## The rule a case must break to race the same read
A background catalog read starts only where the selector has a fetcher and
holds no catalog: `begin_load` returns at once otherwise
(src/provider/model.rs:1560-1565). A fetcher exists only for a keyed Gateway
or a llmux with a URL (`catalog_for`, src/provider/model.rs:991-1007), or one
a case set itself (`set_fetcher_for_test`). The places that start one:
`turn_loop`'s every tick (:3291), `ask_catalog` (:4154), a work's
`CatalogAsks::Reading` on a `TurnControl::Catalog` (:4228), and the in-line
`load_catalog` of `one_turn`'s effort/Fast branch, `image_refusal`,
`change_model` and `await_catalog_for_window` (:4364, :5004, :5629, :5854).

  credential; `catalog_for`'s Gateway arm returns None on
  `config.credential.clone()?` (model.rs:997), the catalog is `Unavailable`
  (model.rs:1467-1471) and no read can start. `recording()` (:9616),
  `published_runtime()` (:7505) and `two_writes` (:14135) are built on it.
- `titled_runtime` (:14786): a Gateway key -> the remote Gateway's catalog,
  unread. FIXED here: an in-process stand-in, pinned as loaded.
- `a_runtime_that_can_open_one` (:13536) and the no-home case (:8044): a key,
  but no case on them runs `turn_loop` or reads the catalog (they call
  `ready`, `adopt`, `conversation`, `title_asker`).
- llmux URLs in fixtures: `127.0.0.1:9` (:12437, `unauthenticated` only) and
  `127.0.0.1:3456` (:13492, :13899, via `adopt`, which builds a selector and
  does no I/O, model.rs:1462-1464); neither case reads the catalog.

## Bridge and the other tui files
src/tui/bridge.rs has no try_recv. approval.rs, question.rs, event_loop.rs,
shell.rs and the rest drain the prompter's, the shell's or their own
channels; none builds a Runtime with a selector or calls turn_loop (the
`turn_loop` hits in shell.rs/approval.rs/question.rs are comments or test
names), so none can race a catalog read.
