## Reading, checked against the code

- The catalog clock counts from boot: `system::BOOT` is `CLOCK_BOOTTIME` on Linux, `CLOCK_MONOTONIC_RAW` on Apple (`src/provider/catalog_clock.rs:220-229`), read as a `Duration` since that origin (`:113-120`, `:239-241`). A machine booted N seconds ago has no reading earlier than N seconds back.
- The three shell tests took `catalog_now().checked_sub(REFRESH_INTERVAL + 1 s).expect("a clock older than five minutes")` (`CatalogTime::checked_sub`, `#[cfg(test)]`, `:38-42`); under 301 s of boot clock it is `None`, and the `expect` panics.
- The worker test went five minutes back through `backdate_catalog` -> `ModelSelector::backdate_for_test`, whose `at.checked_sub(by).unwrap_or(at)` (`src/provider/model.rs`, at 3be49c15 `:2394`) **left the time where it was** when the clock had not counted that far -- not the saturating `Sub` -- so the rows stayed six seconds old, the prompt read nothing, and the third read never came (`left: 2`, `right: 3`).
- **No production code goes back on the catalog clock.** `young-clock.sh sub`: with `impl Sub<Duration> for CatalogTime` made `#[cfg(test)]`, `cargo check --locked --lib` builds with and without `fault-injection` (`CatalogTime` is `pub(crate)`, so the binary cannot use it); `checked_sub` and `checked_duration_since` were `#[cfg(test)]` already. `young_scan.py` finds no site outside a tests module that goes back from a `CatalogTime` or an `Instant` reading (0 of 42 at 3be49c15). And every `CatalogTime` built outside the tests module wraps a raw reading or goes forward: `CatalogTime(reading..)` in `now()` (`:119`), `Self(self.0.saturating_add(by))` for `+` (`:49`), and `Self(self.0.saturating_sub(by))` for `-` (`:57`), which only tests call (the check above). So a test defect, and a young boot clock changes nothing a user runs: a reading is never subtracted from, and `CatalogDue::is_due` only compares.

## The fix (c4354ec7, test code only: every hunk is in a tests module or a `#[cfg(test)]` fn)

- The four tests run on a `FakeMachine` catalog clock (up an hour, so its readings go back as far as a test needs): the three shell tests set the shell's `catalog_clock` and take their readings from it; the worker test sets the selector's (`set_clock_for_test`) before its first read, so its two backdates move readings an hour in. What each pins is unchanged: rows five minutes past their read's start are read again and fresh ones are not; a resume or a fork asks over stale rows only; `/settings` and the speed commands ask for no refresh over stale rows or a failure past its hold; a prompt reads rows again only once they are five minutes old.
- `backdate_for_test` panics, naming `FakeMachine`, when the clock has not counted `by`, instead of leaving the time where it was -- so a backdate past the origin can no longer pass or fail as something else.
- The look-ahead's two other long ones: two event_loop tests gave "a failure past its hold" as a due a minute back (`catalog_due_ago(60 s)`), which a machine booted under a minute ago does not have; each now gives a hold that ends as it is told (`catalog_due(Duration::ZERO)`), due on any boot clock. One of them is train 11's join check 2 (its asks and bytes unchanged, below); the other is `a_catalog_answer_read_in_a_stops_window_reaches_the_band_and_leaves_the_stop_as_it_was`.
