# TUI Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Phase-1 full-repaint TUI with the release-quality Phase-2 surface and prove every canonical Phase-2 scenario on native terminals.

**Architecture:** Keep the Phase-1 ownership model: one UI thread owns terminal bytes and one worker owns the runtime. Add release-quality mechanisms at existing pure seams—grid diffing in the frame writer, resize at the signal/layout boundary, command/history/paste state in focused UI modules, approval screen ownership in the prompter, and terminal modes in the lifecycle layer. Every optimization is observationally equivalent to the Phase-1 full-repaint reference.

**Tech Stack:** Rust stable with the locked dependency graph; `rustix`/`libc` terminal primitives; `unicode-segmentation` and `unicode-width`; handwritten ANSI/OSC/kitty sequences; Python standard library only for `scripts/smoke-tui.sh`.

**Spec:** `.prd/tui-phase2/ssot.md`, implementing `.prd/03-tui-port.md` Phase 2 items 11–17 and `.prd/06-qa-harness.md` scenarios 13–21. Carrier: https://github.com/2lab-ai/xfx/issues/19.

## Global Constraints

- Preserve the normal-buffer/native-scrollback model. Alternate screen is used only by the Phase-2 file-diff approval surface.
- The cell diff is an optimization: its final grid must equal the Phase-1 full-repaint grid for the same facts.
- The UI thread remains the sole reader and writer of terminal bytes. The worker never reads stdin.
- Resize reflows the owned band and unfinished transcript tail. Committed native scrollback remains terminal-owned.
- Tests deliver `SIGWINCH` explicitly after changing PTY winsize; they do not assume a controlling foreground process group.
- A post-launch zero-by-zero winsize is no new information, not the 24×80 startup fallback.
- No async runtime is added to the UI thread. Debounce is a monotonic deadline, never a sleep.
- Provider and model fixtures remain loopback/no-network/no-credential in automated tests.
- RED first. Every mutation is actually executed and its raw failing output is quoted.
- Gate commands are file-redirected and `&&`-chained so pipelines cannot mask failures. Counts are machine-summed.
- `usize` owns counts and indexes. Narrow only at terminal coordinates after clamping.
- PTY wait needles are response-only. State-transition tests enumerate all reachable state sequences.
- Tests pin policy literals instead of importing the values they claim to protect.
- One implementation agent owns the worktree at a time. Review agents are read-only.
- Each task ends with a scoped dual-persona external review. Blocking feedback is fixed and re-reviewed by the same implementer/reviewer pair until unanimous release-ready.
- Stable releases and `v*` tags are forbidden. Final delivery stops at the preview channel plus `brew upgrade xfx-preview` and a captured real-config TUI smoke.
