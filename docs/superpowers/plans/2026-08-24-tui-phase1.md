# xfx TUI Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make xfx a TUI at all — a raw-mode shell that owns a band at the bottom of the *normal* buffer, streams a turn into native scrollback, edits its composer itself, approves mutations inline, and restores the terminal on every exit path — exactly the Phase-1 rung of `.prd/03-tui-port.md`, and nothing above it.

**Architecture:** A new `src/tui/` module owns the terminal on the **main thread** (raw mode, `poll(2)` + 8 ms tick, escape decode, frame commit, signal-flag observation, panic restore). The tokio runtime moves off the main thread into a named worker that runs one turn at a time through the *existing* `agent::run_turn_saved` / `gateway::Provider` / `session::SessionStore` path. Three channels join them (`UiEvent` bounded 256, `TurnControl` unbounded, `TurnWork` capacity 1) and a `CancellationToken` + its `CancelToken` atomic mirror carry cancellation. The line-oriented shell in `src/interactive.rs` stays exactly what it is and stays the default; the TUI is reached by `XFX_TUI=1` for the whole of Phase 1.

**Tech Stack:** Rust 1.96, edition 2021. New dependencies: `tokio-util` (`sync::CancellationToken`, `default-features = false`), `libc` (POSIX `sigaction`/`raise` — already in the lock file at 0.2.189 as a transitive dependency), `unicode-segmentation` + `unicode-width` (grapheme motion and cell width). Existing `rustix` gains the `termios`, `event`, `pipe`, `stdio` features on Unix. **Not** adopted: `crossterm` (its event parser costs the byte-level escape/replay ordering xfx must own), `ratatui` (a fixed bottom `Layout` chunk loses the transcript-scrollback cohabitation model), `syntect`, `pyte`.

**Spec:** [`.prd/03-tui-port.md`](../../../.prd/03-tui-port.md) (authoritative). Companions: [`.prd/06-qa-harness.md`](../../../.prd/06-qa-harness.md) (Phase-1 scenarios, wired in as Task 19), [`.prd/02-architecture.md`](../../../.prd/02-architecture.md) (module map), [`.prd/research/tui-core.md`](../../../.prd/research/tui-core.md) and [`.prd/research/input-footer.md`](../../../.prd/research/input-footer.md) (upstream evidence; every `file:line` in this plan that names a `.zig` file is upstream-relative at `vercel-labs/fx@ef1d0d0` and comes from those notes).

## Global Constraints

These are the spec's own words where the spec is the reason. A step that cannot be done without breaking one of these is a step that stops and reports.

### The one decision that matters (verbatim, `03-tui-port.md` §"The one decision that matters")

> fx's main UI is **not an alternate-screen application.** It owns a band at the bottom of the *normal* buffer. Completed transcript rows are appended to the terminal's own document and live forever in native scrollback; fx repaints only its band (transcript viewport + activity row + footer/composer). Alt screen is an exceptional, exclusively-owned state for modals […] The normal exit restore sequence does not even contain `1049l`, because the main surface was never there (`app_lifecycle.zig:39-41`).

Phase 1 therefore **never writes `\x1b[?1049h`**, and **never enables mouse reporting** (`1000h`/`1002h`/`1006h` are absent — upstream pins the same negative at `terminal.zig:135-142`), because the user's wheel must stay the terminal's own scrollback.

### Runtime topology (verbatim, `03-tui-port.md` §"Runtime topology (authoritative)")

```
UI thread (= main thread)
  raw mode · poll(2)+8ms tick · escape decode · frame commit · signal-flag observation
  owns the terminal exclusively; owns the CancellationToken (+ its atomic mirror); owns panic-restore
        ▲                        │                        │
        │ UiEvent                │ TurnControl            │ TurnWork
        │ bounded ~256           │ UNBOUNDED              │ capacity 1
        │ send().await           │ approval answer,       │ submit prompt,
        │ (never blocking_send)  │ cancel, shutdown       │ /model change
        │                        ▼ drained mid-turn       ▼ full ⇒ UI rejects w/ notice
  runtime thread: current-thread tokio · one turn at a time
                  Provider::stream + tools + session writes
                  panics caught at the task boundary → fatal UiEvent

  signal handlers (process-wide, async-signal-safe only):
    INT/TERM/HUP → restore pair → SIG_DFL → re-raise
    TSTP         → restore pair → SIG_DFL → raise(SIGSTOP)
    CONT         → set atomic resume flag + self-pipe byte  (no work in handler)
    WINCH        → set atomic flag + self-pipe byte

  no xfx-interrupt thread in a TUI session (it remains for `ask` and the pipe paths)
```

| Channel | Direction | Capacity | Carries | Full/closed behavior |
|---|---|---|---|---|
| `UiEvent` | runtime → UI | bounded (~256) | text delta, tool start/result, usage, terminal event | producer **awaits** `send()` inside a `select!` against cancellation — **except the terminal event, whose send is uncancellable**; **never dropped while the UI is live** |
| `TurnControl` | UI → runtime | **unbounded** | approval answer, cancel, shutdown | never blocks, never full; consumed **mid-turn** |
| `TurnWork` | UI → runtime | 1 | submit prompt, `/model` change | full ⇒ UI **rejects with a visible notice**; never silently dropped |

- **Never `tokio::sync::mpsc::Sender::blocking_send`.** It panics inside a runtime rather than backpressuring. The awaited producer is:

  ```rust
  tokio::select! {
      biased;
      _ = cancel.cancelled() => return Err(Cancelled),
      result = events.send(event) => result.map_err(|_| UiGone)?,
  }
  ```

- **The terminal `UiEvent` send is uncancellable** — plain `events.send(event).await`, bounded by the UI's drain deadline, and written so the exception is visible at the call site.
- **Cancellation ordering is fixed: set the atomic mirror first (`Release`), then cancel the token.** Nothing clears either one; a new turn takes a fresh child token and a reset mirror.
- **Shutdown is the drain protocol**: cancel + `TurnControl::Shutdown` → UI keeps receiving and committing under a deadline → worker publishes its session log and sends exactly one terminal `UiEvent` → UI leaves the drain loop, *then* joins → on deadline the UI drops the receiver so a parked `send().await` resolves `Err`. After its terminal event the worker uses `try_send` and discards on full. Restoration runs even if the join times out.

**One deviation from the letter of the topology, and the reason.** `output::EventSink::emit` and `gateway::DeltaSink::text_delta` are **synchronous** traits, and `gateway/` is off-limits to this plan (see BOUNDARY below), so the turn's producer callbacks cannot be made `async` here. The spec's own escape hatch covers this case — *"If any genuinely synchronous producer remains […] it uses a sync bridge"* — but its suggested `blocking_send` is wrong inside a runtime. This plan therefore lands `tui::bridge::park_on`, a ~30-line `std::task::Wake` mini-executor that **polls the very `select!` above** on the worker's own thread: cancellation still wins by wakeup (not by flag polling), nothing is dropped, order is preserved, backpressure reaches the SSE decode because the socket is not polled while parked, and no tokio API panics. It is used at exactly two seams (the `UiEvent` sink and the approval prompter) and both are named in `src/tui/bridge.rs`'s module header.

### The signal contract (`03-tui-port.md` §"Signals")

| Signal | Handler does |
|---|---|
| SIGINT | **The handler exists** (`ISIG` only suppresses *terminal-generated* SIGINT). Restore pair → `SIG_DFL` → re-raise |
| SIGTERM, SIGHUP | `write(2)` the compile-time-constant restore bytes → `tcsetattr(TCSAFLUSH)` the `termios` saved at entry → `SIG_DFL` → `raise` |
| SIGTSTP | The restore pair → `SIG_DFL` → `raise(SIGSTOP)`. **Nothing else** |
| SIGCONT | Set the atomic `resumed` flag (`Release`), **then** one byte to the non-blocking self-pipe, ignoring `EAGAIN`. That is all |
| SIGWINCH | Same shape: atomic flag, then a best-effort self-pipe byte |
| SIGPIPE | ignored |

- The self-pipe: **both ends `O_NONBLOCK` and `FD_CLOEXEC`**; write only on a false→true transition (`swap(true, AcqRel) == false`); the read end drains greedily until `EAGAIN` and the bytes are discarded — they are a wakeup, never data.
- `poll(2)` watches **stdin and the self-pipe read end**. `EINTR` is a normal wakeup, not an error. Handlers are installed **without `SA_RESTART`** so a parked `read`/`poll` returns.
- **The TSTP reinstall is not optional**: after the first Ctrl-Z the disposition is default, so resume must `sigaction` SIGTSTP again on the UI thread before anything else.
- The original `termios` is captured **once at entry, before raw mode**, into a write-once global; a handler allocates nothing and takes no lock.
- **A handler restores and re-raises, or it sets a flag. It never repaints.**

### Panic ownership (`03-tui-port.md` §"Panic ownership")

- Record the UI thread's `ThreadId` when it takes ownership (immediately after raw mode is entered), in the same write-once global that holds the saved `termios`.
- The global hook restores **only** when `std::thread::current().id()` equals that id, before the default hook prints.
- A worker panic never touches the terminal: it is caught at the task boundary and delivered as a **fatal `UiEvent`**; the UI leaves the drain loop, joins, restores, prints, exits nonzero.

### Terminal-state acceptance is two-sided (`03-tui-port.md` §"Acceptance — terminal state, positively proven")

Byte-identical `termios` after exit is **necessary and not sufficient** — a build that never entered raw mode passes it. Every phase-1 task that touches the terminal owes both halves:

1. **Positive proof of entry**, read from the *child's* terminal while it runs: `ECHO`, `ICANON`, `IEXTEN`, `ISIG` clear in `c_lflag`; `IXON`, `ICRNL`, `BRKINT`, `INPCK`, `ISTRIP` clear in `c_iflag`; `CS8` set; `VMIN == 1`, `VTIME == 0` (`shell_runtime.zig:108-138`). Plus `?2004h` and `?7l` present, `1000h`/`1002h`/`1006h` absent, and under a simulated tmux the kitty push `\x1b[>1u` absent (`terminal.zig:29-34`).
2. **One restoration case per exit path**: normal `/quit`, UI-thread panic, worker panic, SIGTERM/SIGHUP (`WIFSIGNALED`), SIGTSTP/SIGCONT (`WIFSTOPPED`) **and a second SIGTSTP after resume**, partial initialization (after raw mode → restored; before raw mode → **no** restore bytes at all), external SIGINT (`WIFSIGNALED`), and terminal Ctrl-C (`0x03` delivers **no** signal — the byte cancels the turn, a second exits 130).

### The ledger discipline (`06-qa-harness.md` §"Acceptance criteria per phase" #6)

> `docs/parity.md` is updated in the same change for anything the phase made advertisable, and nothing the phase did **not** finish is advertised anywhere.

Every task below that changes what the binary can do carries its **exact** `docs/parity.md` row edit as a numbered step, in the same commit as the code. `scripts/check-no-stubs.sh` and `tests/parity.rs` reconcile the ledger in both directions; they parse a row as `| surface | kind | status | notes |` and only *backticked* surface names are machine-checked, so the prose `ui` rows this plan edits are held honest by review and by the QA gate, not by a script. The pasted-block collapse in Task 18 is therefore spelled `[Pasted text #N, M lines]` and its Rust identifiers are `pasted_block` / `collapse`, never `placeholder`, in any string.
- Phase 1 adds **no** command, no tool, and no slash name. `interactive::SLASH_COMMANDS` stays the same six; the TUI answers exactly those six and nothing else.

> **Addendum, executed in Task 12 (orchestrator ruling).** This line made the six a Phase-1 contract, and the task list then gave the routing to nobody — a self-review miss caught once Task 11 made `Shell::submit` reachable, at which point `/help` was being sent to the model as a prompt. No name was added.

### BOUNDARY (cross-plan, binding)

A parallel plan owns the provider engine. **This plan must not touch `src/gateway/`, `src/llmux/`, or provider selection.** The TUI calls `app::build_provider(&config, &cancel)` unchanged and keeps the shell's existing `/model` semantics: `/model` with no argument reports, `/model <id>` records a `PreferencesChanged` event and applies to later turns — the same rules `interactive::apply_model` has today. No backend, endpoint, catalog, or picker work is in scope.

```rust
/// The child's process id, for a test that has to signal it rather than type at it.
impl Session {
    pub fn pid(&self) -> Pid {
        Pid::from_raw(self.child.id() as i32).expect("the child has a pid")
    }

    /// Sends `signal` to the child, exactly as an operator or a supervisor would.
    pub fn signal(&self, signal: Signal) {
        rustix::process::kill_process(self.pid(), signal).expect("signal the child");
    }

    /// Waits until `ready` describes the child, so a test can assert on a
    /// process that is *stopped* -- which `Child::try_wait` cannot report,
    /// because it does not pass `WUNTRACED`.
    pub fn wait_state(&self, what: &str, ready: impl Fn(&Wait) -> bool) -> Wait {
        let deadline = Instant::now() + WAIT;
        loop {
            let state = wait_state(self.pid());
            if ready(&state) {
                return state;
            }
            assert!(
                Instant::now() < deadline,
                "timed out waiting for {what}; child is {state:?}; terminal so far:\n{}",
                self.text()
            );
            thread::sleep(Duration::from_millis(10));
        }
    }
}

/// What a child is doing, including the one state `Child::try_wait` hides.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Wait {
    Running,
    Stopped(i32),
    Exited(i32),
    Signalled(i32),
}

pub fn wait_state(pid: Pid) -> Wait {
    match rustix::process::waitpid(
        Some(pid),
        WaitOptions::NOHANG | WaitOptions::UNTRACED | WaitOptions::CONTINUED,
    ) {
        Ok(None) => Wait::Running,
        Ok(Some((_, status))) => {
            if let Some(signal) = status.stopping_signal() {
                Wait::Stopped(signal)
            } else if let Some(signal) = status.terminating_signal() {
                Wait::Signalled(signal)
            } else if let Some(code) = status.exit_status() {
                Wait::Exited(code)
            } else {
                Wait::Running
            }
        }
        Err(_) => Wait::Running,
    }
}

impl Pty {
    /// Fixes the terminal's dimensions before a child is spawned, so a layout
    /// assertion is about geometry rather than about whatever window the
    /// developer happened to have open.
    pub fn resize(&self, rows: u16, cols: u16) {
        let size = Winsize {
            ws_row: rows,
            ws_col: cols,
            ws_xpixel: 0,
            ws_ypixel: 0,
        };
        let slave = self.slave.as_ref().expect("the harness retains a slave");
        rustix::termios::tcsetwinsize(slave.as_fd(), size).expect("set the pty size");
    }
}
```

```rust
//! The terminal xfx borrows, and the exact shape in which it gives it back.
//!
//! Two things live here because a signal handler needs them: the `termios` the
//! process captured **once, before raw mode**, and the compile-time-constant
//! restore strings. A handler allocates nothing, takes no lock, and touches
//! nothing else (`vercel-labs/fx@ef1d0d0 src/core/app/app_lifecycle.zig:36-68`).

use std::io::{self, Write};
use std::os::fd::{AsFd, BorrowedFd, RawFd};
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::OnceLock;
use std::thread::ThreadId;

use rustix::termios::{
    tcgetattr, tcsetattr, ControlModes, InputModes, LocalModes, OptionalActions, SpecialCodeIndex,
    Termios,
};

// ... the constants from the Interfaces block above ...

/// What the process captured on the way in, and who is allowed to give it back.
struct Owned {
    termios: Termios,
    fd: RawFd,
    ui_thread: ThreadId,
}

static OWNED: OnceLock<Owned> = OnceLock::new();
static TMUX: AtomicBool = AtomicBool::new(false);

pub(crate) fn under_tmux() -> bool {
    std::env::var_os("TMUX").is_some_and(|value| !value.is_empty())
}

pub(crate) fn capture(fd: BorrowedFd<'_>) -> io::Result<Termios> {
    tcgetattr(fd).map_err(io::Error::from)
}

pub(crate) fn raw_from(saved: &Termios) -> Termios {
    let mut raw = saved.clone();
    raw.input_modes.remove(
        InputModes::BRKINT
            | InputModes::ICRNL
            | InputModes::INPCK
            | InputModes::ISTRIP
            | InputModes::IXON
            | InputModes::IXOFF,
    );
    raw.control_modes.insert(ControlModes::CS8);
    raw.local_modes.remove(
        LocalModes::ECHO | LocalModes::ICANON | LocalModes::IEXTEN | LocalModes::ISIG,
    );
    raw.special_codes[SpecialCodeIndex::VMIN] = 1;
    raw.special_codes[SpecialCodeIndex::VTIME] = 0;
    raw
}

pub(crate) fn enter_raw(fd: BorrowedFd<'_>, saved: &Termios) -> io::Result<()> {
    tcsetattr(fd, OptionalActions::Flush, &raw_from(saved)).map_err(io::Error::from)
}

/// Records what a handler will need, and who owns the terminal.
///
/// Write-once and never written again, so a handler can reach it without a lock
/// (`03-tui-port.md` §"Signals"). Called immediately after raw mode is entered,
/// which is also the moment the UI thread takes ownership for panic purposes.
pub(crate) fn adopt(fd: RawFd, saved: Termios, tmux: bool) {
    TMUX.store(tmux, Ordering::Release);
    let _ = OWNED.set(Owned {
        termios: saved,
        fd,
        ui_thread: std::thread::current().id(),
    });
}

pub(crate) fn ui_thread() -> Option<ThreadId> {
    OWNED.get().map(|owned| owned.ui_thread)
}

/// The restore pair, from a context that may allocate nothing.
///
/// Escape bytes restore *screen* state; only `tcsetattr` restores the line
/// discipline, and POSIX lists it among the async-signal-safe functions. Both
/// return values are ignored on purpose: there is no one left to report to.
pub(crate) fn restore_pair() {
    let Some(owned) = OWNED.get() else { return };
    let bytes = if TMUX.load(Ordering::Acquire) {
        ABNORMAL_RESTORE_TMUX
    } else {
        ABNORMAL_RESTORE
    }
    .as_bytes();
    // SAFETY: `write` is async-signal-safe, the fd was captured at entry and is
    // owned by the process for its whole life, and the buffer is 'static.
    unsafe {
        libc::write(owned.fd, bytes.as_ptr().cast(), bytes.len());
    }
    // SAFETY: the fd is the one this process captured; `borrow_raw` does not
    // take ownership and the descriptor outlives the call.
    let fd = unsafe { BorrowedFd::borrow_raw(owned.fd) };
    let _ = tcsetattr(fd, OptionalActions::Flush, &owned.termios);
}

/// The normal exit, in upstream's order (`app_lifecycle.zig:578-593`).
///
/// There is no alternate screen to leave, because the main surface was never on
/// one -- which is why [`RESTORE`] contains no `1049l`.
pub(crate) fn shutdown(band_top: u16) -> io::Result<()> {
    let Some(owned) = OWNED.get() else { return Ok(()) };
    let restore = if TMUX.load(Ordering::Acquire) { RESTORE_TMUX } else { RESTORE };
    let mut out = io::stdout().lock();
    write!(out, "{restore}")?;
    out.flush()?;
    let fd = unsafe { BorrowedFd::borrow_raw(owned.fd) };
    tcsetattr(fd, OptionalActions::Flush, &owned.termios).map_err(io::Error::from)?;
    // Leave the transcript in scrollback and the cursor on a clean line.
    write!(out, "\x1b[{band_top};1H\x1b[J\x1b[?25h\n")?;
    out.flush()
}
```

```rust
//! The Phase-1 TUI: a raw-mode shell that owns a band at the bottom of the
//! terminal's **normal** buffer.
//!
//! It is reached by `XFX_TUI=1` on a bare `xfx` and by nothing else, because it
//! is narrower than the line-oriented shell it sits beside; `docs/parity.md`
//! states exactly how much narrower. The UI thread here is the process's main
//! thread and it owns the terminal exclusively: nothing else writes a byte to
//! stdout, which is what makes "what is on the terminal is what this module
//! wrote" a property rather than a hope (`.prd/03-tui-port.md`).

use std::io::{self, IsTerminal, Write};
use std::os::fd::AsFd;
use std::process::ExitCode;

use crate::cli::{Cli, Command};

/// The variable that opts a bare invocation into the TUI.
pub const TUI_ENV: &str = "XFX_TUI";

/// Whether this invocation is the one the TUI owns.
///
/// A bare `xfx`, `XFX_TUI=1`, and a real terminal on both ends. Anything else --
/// a subcommand, a pipe, an unset or different value -- is the line-oriented
/// shell or an ordinary command, unchanged.
pub fn should_run(cli: &Cli) -> bool {
    matches!(cli.command, Command::Interactive)
        && std::env::var_os(TUI_ENV).is_some_and(|value| value == "1")
        && io::stdin().is_terminal()
        && io::stdout().is_terminal()
}

/// Runs the TUI on the calling thread, which must be the process's main thread.
pub fn run_blocking(_cli: Cli) -> ExitCode {
    let config = match crate::app::load_config() {
        Ok(config) => config,
        Err(err) => return fail(&format!("{err}")),
    };
    match session(&config) {
        Ok(code) => code,
        Err(err) => fail(&format!("{err}")),
    }
}

fn session(_config: &crate::config::RuntimeConfig) -> io::Result<ExitCode> {
    let stdin = io::stdin();
    let saved = term::capture(stdin.as_fd())?;
    term::enter_raw(stdin.as_fd(), &saved)?;
    let tmux = term::under_tmux();
    term::adopt(rustix::stdio::raw_stdout(), saved, tmux);

    let mut out = io::stdout().lock();
    write!(out, "{}", if tmux { term::MODE_SET_TMUX } else { term::MODE_SET })?;
    out.flush()?;
    drop(out);

    // Phase 1, task 2: one byte of input, and the exit path. The poll loop
    // arrives in task 6; Ctrl-D leaving is the shell's own contract and stays.
    let mut byte = [0u8; 1];
    loop {
        match io::Read::read(&mut io::stdin(), &mut byte) {
            // End of input, and Ctrl-D: the shell's own contract is that
            // Ctrl-D leaves, and it survives every later task.
            Ok(0) => break,
            Ok(_) if byte[0] == 0x04 => break,
            Ok(_) => continue,
            Err(err) if err.kind() == io::ErrorKind::Interrupted => continue,
            Err(err) => return Err(err),
        }
    }
    term::shutdown(1)?;
    Ok(ExitCode::SUCCESS)
}

fn fail(message: &str) -> ExitCode {
    let _ = writeln!(io::stderr(), "xfx: {message}");
    ExitCode::FAILURE
}

mod term;
```

```rust
//! One owner per signal, and nothing in a handler that is not async-signal-safe.
//!
//! A handler restores and re-raises, or it sets a flag. It never repaints and
//! never returns into the UI's frame state: a cooked terminal with a stale band
//! is a recoverable annoyance, a terminal left raw is not
//! (`.prd/03-tui-port.md` §"Signals").

use std::io;
use std::os::fd::{AsFd, AsRawFd, BorrowedFd, OwnedFd};
use std::sync::atomic::{AtomicBool, AtomicI32, Ordering};

use rustix::io::FdFlags;

use super::term;

static RESUMED: AtomicBool = AtomicBool::new(false);
static WINCH: AtomicBool = AtomicBool::new(false);
/// The write end, for the handlers. `-1` until [`install`] runs.
static POKE: AtomicI32 = AtomicI32::new(-1);

/// The self-pipe a handler pokes so a parked `poll(2)` wakes now rather than at
/// the next tick.
pub(crate) struct Wakeup {
    read: OwnedFd,
    write: OwnedFd,
}

impl Wakeup {
    /// Both ends non-blocking and close-on-exec.
    ///
    /// `pipe2` is not portable (macOS has no such call), so the flags are set
    /// with `fcntl` afterwards. Non-blocking on the **write** end is the
    /// load-bearing one: a full pipe must make the handler drop the byte, not
    /// block the UI thread with the terminal raw. Close-on-exec keeps a spawned
    /// command from inheriting either end.
    pub(crate) fn new() -> io::Result<Self> {
        let (read, write) = rustix::pipe::pipe()?;
        for end in [read.as_fd(), write.as_fd()] {
            let flags = rustix::fs::fcntl_getfl(end)?;
            rustix::fs::fcntl_setfl(end, flags | rustix::fs::OFlags::NONBLOCK)?;
            rustix::io::fcntl_setfd(end, FdFlags::CLOEXEC)?;
        }
        Ok(Self { read, write })
    }

    pub(crate) fn read_fd(&self) -> BorrowedFd<'_> {
        self.read.as_fd()
    }

    /// Reads until `EAGAIN` and discards everything: the bytes are a wakeup,
    /// never data.
    pub(crate) fn drain(&self) {
        let mut scratch = [0u8; 64];
        while let Ok(read) = rustix::io::read(&self.read, &mut scratch) {
            if read == 0 {
                break;
            }
        }
    }
}

/// Installs every handler the TUI owns, without `SA_RESTART`.
///
/// The missing `SA_RESTART` is deliberate: a `poll(2)` or `read(2)` parked when
/// a signal arrives must return `EINTR` so the UI thread gets a turn.
pub(crate) fn install(wakeup: &Wakeup) -> io::Result<()> {
    POKE.store(wakeup.write.as_raw_fd(), Ordering::Release);
    unsafe {
        handler(libc::SIGINT, restore_and_reraise)?;
        handler(libc::SIGTERM, restore_and_reraise)?;
        handler(libc::SIGHUP, restore_and_reraise)?;
        handler(libc::SIGTSTP, stop_for_job_control)?;
        handler(libc::SIGCONT, flag_resumed)?;
        handler(libc::SIGWINCH, flag_winch)?;
        // The UI owns one terminal; a failed write is handled by its return
        // value, not by dying.
        libc::signal(libc::SIGPIPE, libc::SIG_IGN);
    }
    Ok(())
}

/// Reinstalls the SIGTSTP handler after a resume.
///
/// Not optional: [`stop_for_job_control`] resets the disposition to default
/// before raising, so after one Ctrl-Z a second would stop the process with the
/// terminal still raw. `sigaction` on the UI thread is unconstrained, which is
/// why this belongs here and not in the handler.
pub(crate) fn install_tstp() -> io::Result<()> {
    unsafe { handler(libc::SIGTSTP, stop_for_job_control) }
}

unsafe fn handler(signal: libc::c_int, func: extern "C" fn(libc::c_int)) -> io::Result<()> {
    let mut action: libc::sigaction = std::mem::zeroed();
    action.sa_sigaction = func as usize;
    libc::sigemptyset(&mut action.sa_mask);
    action.sa_flags = 0;
    if libc::sigaction(signal, &action, std::ptr::null_mut()) != 0 {
        return Err(io::Error::last_os_error());
    }
    Ok(())
}

extern "C" fn restore_and_reraise(signal: libc::c_int) {
    term::restore_pair();
    unsafe {
        libc::signal(signal, libc::SIG_DFL);
        libc::raise(signal);
    }
}

extern "C" fn stop_for_job_control(_signal: libc::c_int) {
    term::restore_pair();
    unsafe {
        libc::signal(libc::SIGTSTP, libc::SIG_DFL);
        libc::raise(libc::SIGSTOP);
    }
}

extern "C" fn flag_resumed(_signal: libc::c_int) {
    if !RESUMED.swap(true, Ordering::AcqRel) {
        poke();
    }
}

extern "C" fn flag_winch(_signal: libc::c_int) {
    if !WINCH.swap(true, Ordering::AcqRel) {
        poke();
    }
}

/// One byte, best effort. A full pipe means a wakeup is already queued, and the
/// *fact* of the signal lives in the atomic rather than in the byte.
fn poke() {
    let fd = POKE.load(Ordering::Acquire);
    if fd >= 0 {
        let byte = [1u8];
        // SAFETY: `write` is async-signal-safe; a short write and `EAGAIN` are
        // both ignored on purpose.
        unsafe {
            libc::write(fd, byte.as_ptr().cast(), 1);
        }
    }
}

pub(crate) fn take_resumed() -> bool {
    RESUMED.swap(false, Ordering::AcqRel)
}

/// Phase 1 records the resize and acts on nothing: re-layout is Phase 2 item 12,
/// and `docs/parity.md` says so. The flag exists here because the signal
/// contract is one unit and a half-installed handler set is the bug this
/// section exists to avoid.
pub(crate) fn take_winch() -> bool {
    WINCH.swap(false, Ordering::AcqRel)
}
```

```rust
///
/// Order matters: reinstall the handler first, because the window in which a
/// second Ctrl-Z would hit the default disposition is open until it is closed

    // terminal while this process was stopped. The write-once original stays
    // what it was -- that is what a handler restores to.
    let current = term::capture(stdin.as_fd())?;
    term::enter_raw(stdin.as_fd(), &current)?;
    let mut out = io::stdout().lock();
    write!(out, "{}", if tmux { term::MODE_SET_TMUX } else { term::MODE_SET })?;
    out.flush()
}
```

```rust
//! Who restores the terminal when the process is coming apart.
//!
//! A panic is not a signal, and the restore must be done by the thread that
//! owns the terminal. A hook that restored unconditionally would let a worker
//! panic mutate terminal state while the UI thread is still painting, which is
//! the same double-writer bug the single-writer rule exists to prevent.

use super::term;

/// Installs the hook that restores only for the UI thread.
pub(crate) fn install_hook() {
    let previous = std::panic::take_hook();
    std::panic::set_hook(Box::new(move |info| {
        if term::ui_thread() == Some(std::thread::current().id()) {
            // Before the default hook prints, so the message lands on a cooked
            // terminal and is readable rather than painted into a torn band.
            term::restore_pair();
        }
        previous(info);
    }));
}
```

- [ ] **Step 3: Implement the probe**

The state machine is four states (`Idle`, `Esc`, `Csi`, `Row`, `Col`), it buffers at most 16 bytes, and any byte that breaks the shape returns the **first** buffered byte as `NotMine` and re-feeds the rest — the same "one byte produces at most one event" discipline the input decoder keeps (`terminal_action_decoder.zig:105-114`). `read_reply` writes `QUERY`, then reads stdin with a 100 ms deadline (`shell_runtime.zig:178-206`), feeding each byte into the probe and **retaining** every `NotMine` byte in a deferred buffer that the event loop drains before its first `poll` — a user who typed while the probe was in flight must not lose the keystroke.

`scrollback_push(cursor_row, rows) = min(cursor_row, rows).saturating_sub(1)`.

- [ ] **Step 3: Implement layout, frame, and render requests**

`solve` computes, in one pass and in this order (the fixed-point convergence upstream does is Phase 3 item 22, and the one-pass approximation is stated in the module header): `hint = rows`, `input_last = rows - 1`, `input_first = input_last + 1 - input_rows`, `divider = input_first - 1`, `content_bottom = divider - 1`. It returns `None` when `rows < MIN_ROWS`, `cols < MIN_COLS`, or the composer would leave no content area — a terminal too small is a named refusal on stderr, never a band painted over the user's screen.

`Band::render` builds one buffer: `?2026h` `?25l` `CUP(divider,1)` `\x1b[J` then one `CUP(row,1)` + clipped row text per band row, then `CUP(cursor)`, `?2026l`, `?25h`. `commit` is `render` + one `write_all` + `flush` on the locked stdout — **one write per frame**, because the single-writer rule is what makes the band's state knowable. `render_append` normalizes CR-before-LF, emits `CUP(rows,1)` + one `\n` per appended visual row, then places the rows above the band with CUP.

`term::window_size()` (Task 2) reads `rustix::termios::tcgetwinsize(stdout)` and falls back to 24x80 when the terminal will not say; `layout::solve` never queries anything, which is what keeps it unit-testable.

- [ ] **Step 4: Implement the loop**

> **Correction (Task 3 ruling, Task 6 r1 finding — executed).** The `poll(2)` + `WOULDBLOCK`
> read burst this step first prescribed is **unsound on two counts**, and neither is a detail
> the implementation could paper over:
>
> 1. *A `poll` reopens the startup race.* Unmasking and waiting are two operations there, so a
>    `SIGTSTP` delivered between them is delivered **outside** the wait — and the handler hands
>    the terminal back cooked, leaving the session reading and painting a terminal the user's
>    shell has had back since. The unmask and the wait have to be **one** operation, which is
>    `pselect(2)` carrying the mask. Not `ppoll`: it is Linux-only, macOS has no such call, and
>    `pselect` is the portable spelling of the same atomicity.
> 2. *`WOULDBLOCK` never comes.* Standard input is a **blocking** descriptor, so a burst that
>    simply reads again parks the UI thread inside `read(2)` with the frame it owes unpainted.
>    Every read past the first needs its own readability check.
>
> Both are answered by one generalized call, which is the module's whole interface to waiting
> and what landed in `src/tui/signals.rs`:
>
> ```rust
> pub(crate) fn wait_for_input(
>     fds: &[BorrowedFd<'_>],
>     timeout: Option<Duration>,
>     held: &Held,
> ) -> io::Result<bool>;
> ```
>
> `Ok(true)` means at least one descriptor is readable, `Ok(false)` that the timeout passed
> with nothing to read, and `ErrorKind::Interrupted` that a signal was delivered *inside* the
> wait — which is where every stop and every resume in this design happens. The `TICK` is
> expressed as this call's `timeout` for that reason and no other. The invariant it buys, and
> which the rest of the TUI is built on: **while the terminal is raw, `SIGTSTP` is either
> blocked or the process is inside `wait_for_input`.**

`event_loop::run` is upstream's iteration, in order (`event_loop.zig:76-122`):

```rust
loop {
    // The tick is this call's timeout rather than a `poll`'s, so the unmask and
    // the wait are one operation and no stop can land outside the wait.
    match signals::wait_for_input(&[stdin.as_fd(), wakeup.read_fd()], Some(TICK), held) {
        Ok(_) => {}
        // A signal, not a failure: no handler carries `SA_RESTART`, precisely so
        // that a delivered signal ends the wait and the UI thread gets a turn.
        Err(err) if err.kind() == io::ErrorKind::Interrupted => {}
        Err(err) => return Err(err),
    }
    // Before a byte is read: a stop delivered in the wait above handed the
    // terminal back cooked, and reading a cooked terminal reads lines the line
    // discipline assembled rather than the keystrokes this session decodes.
    let reconciled = collect_facts(shell, launch)?;   // resume, resize flag, wakeup drain
    // At most READ_BURSTS x BURST_BYTES, so sustained input cannot starve the
    // paint -- and each read past the first is preceded by its own zero-timeout
    // `wait_for_input`, because stdin blocks and "there was something a moment
    // ago" is not a licence to read again. The token is consumed here.
    read_burst(shell, &stdin, &mut buffer, launch, reconciled)?;
    shell.settle_input(Instant::now());   // a lone ESC, once it has been quiet 50 ms
    take_ui_events(shell, events);        // text, not terminal state
    // And again before anything is painted: the burst's own readiness checks are
    // waits too, so a stop could have landed inside one of them.
    let reconciled = collect_facts(shell, launch)?;
    commit_frame(shell, band, out, failures, Instant::now(), reconciled)?;
    if shell.leaving() { return Ok(shell.exit_code()); }
}
```

Two reconciles per turn, not one, and the **compiler** keeps that rather than a comment: `collect_facts` is the only thing that makes a `#[must_use] Reconciled`, reading and painting are the only things that take one, and each takes it **by value**. Deleting either reconcile does not produce a subtle repaint onto a cooked terminal; it fails the build.

Phase 1's `collect_facts` handles exactly three facts: the resume flag (Task 3's `resume`, moved here), the resize flag (taken and dropped, with the comment naming Phase 2 item 12), and the wakeup drain — which is not optional in the turn that waits on the pipe: a poked pipe nobody read stays readable, and the wait it is part of returns immediately, forever. Task 11 adds the `UiEvent` drain to the same function.

```rust
/// Drives `future` to completion on the calling thread.
///
/// The two synchronous seams the turn machine owns -- `output::EventSink` and
/// `permission::ApprovalPrompter`, both defined outside this module -- have to
/// reach an async channel. `tokio::sync::mpsc::Sender::blocking_send` is not
/// the answer: called from inside a runtime it **panics** rather than applying
/// backpressure. Polling the real future here instead keeps every property the
/// awaited producer has -- cancellation wins by wakeup, order is preserved,
/// nothing is dropped, and the socket is not polled while the thread is parked,
/// which is exactly the backpressure the decode should feel.
pub(crate) fn park_on<F: Future>(future: F) -> F::Output {
    struct Unpark {
        thread: std::thread::Thread,
        woken: AtomicBool,
    }
    impl Wake for Unpark {
        fn wake(self: Arc<Self>) { self.wake_by_ref() }
        fn wake_by_ref(self: &Arc<Self>) {
            self.woken.store(true, Ordering::Release);
            self.thread.unpark();
        }
    }

    let mut future = std::pin::pin!(future);
    let unpark = Arc::new(Unpark {
        thread: std::thread::current(),
        woken: AtomicBool::new(false),
    });
    let waker = Waker::from(Arc::clone(&unpark));
    let mut context = Context::from_waker(&waker);
    loop {
        if let Poll::Ready(output) = future.as_mut().poll(&mut context) {
            return output;
        }
        while !unpark.woken.swap(false, Ordering::AcqRel) {
            std::thread::park();
        }
    }
}
```

`send_ui` is the `select!` from the Global Constraints, verbatim. `send_terminal` is a plain `.await` with the exception documented at the call site. `Cancellation::cancel` writes the mirror with `Release` and then cancels the token; `turn()` resets the mirror and returns a fresh `child_token()`. `UiEventSink::emit` maps `Event` to `UiEvent` and `park_on(send_ui(..))`, turning `Stopped` into `io::ErrorKind::Interrupted` when the token is cancelled and `BrokenPipe` when the UI is gone — which is how the turn machine already reports a sink that failed (`machine.rs:633-648`).

```rust
/// The runtime thread. One turn at a time, on a current-thread runtime, so
/// nothing outlives the command -- the same promise `main` makes for every
/// other invocation, moved off the main thread because the UI needs that one.
pub(crate) fn spawn(config: RuntimeConfig, model: String, cancel: Cancellation)
    -> io::Result<(Worker, Receiver<UiEvent>)>
{
    let (events_tx, events_rx) = mpsc::channel(bridge::UI_EVENTS);
    let (work_tx, mut work_rx) = mpsc::channel::<TurnWork>(1);
    let (control_tx, control_rx) = mpsc::unbounded_channel::<TurnControl>();
    let thread = std::thread::Builder::new()
        .name("xfx-turn".to_string())
        .spawn(move || {
            let Ok(runtime) = tokio::runtime::Builder::new_current_thread().enable_all().build() else {
                // Nothing can run; say so through the one channel the UI reads.
                let _ = events_tx.blocking_send(UiEvent::Fatal("cannot start the async runtime".into()));
                return;
            };
            runtime.block_on(turn_loop(config, model, events_tx, &mut work_rx, control_rx, cancel));
        })?;
    Ok((Worker { thread: Some(thread), work: work_tx, control: control_tx }, events_rx))
}
```

`turn_loop` between turns takes **control first, then at most one work item**; a `Shutdown` breaks the loop, a stray `Answer` is discarded, a `Cancel` between turns is a no-op. A `Submit` runs the turn: `open_conversation` on first use (the same call the line shell makes), `ProjectContext::discover`, a `TurnRequest` with `cancel.turn().mirror`, a `UiEventSink`, and `run_turn_saved`, the whole body inside `AssertUnwindSafe(..).catch_unwind()` so a panic becomes `UiEvent::Fatal(message)` rather than an unwinding thread. Every turn ends with exactly one terminal event sent through `send_terminal`. `TurnWork::Model` applies the shell's existing `/model` semantics — record `SessionEvent::PreferencesChanged`, use it from the next turn on — and nothing else; provider selection is not this plan's.

**The permission session is built here and it does not use `app::permission_session`.** That helper attaches `TtyPrompter`, which reads a line from stdin — the descriptor the UI thread owns and is polling. Two readers on one terminal is the bug this whole topology exists to prevent. Until Task 17 the worker builds `PermissionSession::new(mode).with_durable_session(id)` with **no prompter at all**, so `ask` mode denies mutations with `NoApprovalChannel` — fail-closed, visible, and stated in the ledger in Step 6.

`Worker::shutdown` is the drain protocol, in order, with the reason for each step in a comment: cancel (mirror then token) → `TurnControl::Shutdown` → **keep receiving and painting** until a terminal event or a closed channel or the deadline → drop the receiver on the deadline → join with a short bounded wait → return regardless, because the caller restores the terminal either way.

`fault::Fault`'s `WorkerTurn` arm panics inside the turn body with the message `a turn panicked`, and `SlowUi` makes the event loop sleep 40 ms per frame, which is what fills the `UiEvent` channel and parks the producer in `send().await`.

```rust
/// Every SGR sequence in the captured stream, in order.
fn sgr_runs(text: &str) -> Vec<String> {
    let mut runs = Vec::new();
    let bytes = text.as_bytes();
    let mut index = 0;
    while let Some(found) = text[index..].find("\u{1b}[") {
        let start = index + found;
        let mut end = start + 2;
        while end < bytes.len() && (bytes[end].is_ascii_digit() || bytes[end] == b';') {
            end += 1;
        }
        if end < bytes.len() && bytes[end] == b'm' {
            runs.push(text[start..=end].to_string());
        }
        index = end.min(bytes.len());
    }
    runs
}
```

```rust
fn elapsed_on_activity_row(text: &str) -> Option<u64> {
    let mut latest = None;
    let bytes = text.as_bytes();
    for (index, byte) in bytes.iter().enumerate() {
        if *byte != b's' {
            continue;
        }
        let start = text[..index]
            .rfind(|c: char| !c.is_ascii_digit())
            .map_or(0, |boundary| boundary + 1);
        if start < index {
            if let Ok(seconds) = text[start..index].parse::<u64>() {
                latest = Some(seconds);
            }
        }
    }
```

```python
class Grid:
    """A bounded VT: exactly the sequences xfx says it emits, and nothing else.

    An unknown sequence is a failure rather than a shrug, so the emulator pins
    the emitted subset as well as reading it.
    """

    def __init__(self, rows, cols):
        self.rows, self.cols = rows, cols
        self.cells = [[" "] * cols for _ in range(rows)]
        self.attrs = [[""] * cols for _ in range(rows)]
        self.row = self.col = 0
        self.sgr = ""
        self.unknown = []

    def feed(self, data):
        index = 0
        while index < len(data):
            byte = data[index]
            if byte == 0x1B:
                index = self._escape(data, index)
                continue
            if byte == 0x0A:
                self._newline()
            elif byte == 0x0D:
                self.col = 0
            else:
                self._put(chr(byte))
            index += 1

    def _escape(self, data, index):
        match = CSI.match(data, index)          # ESC [ params intermediates final
        if not match:
            match = OSC.match(data, index)      # ESC ] ... BEL | ESC \
            if not match:
                self.unknown.append(data[index:index + 8])
                return index + 1
            return match.end()                  # OSC changes no cell
        params, final = match.group("params"), match.group("final")
        if final == "H":                        # CUP
            row, _, col = params.partition(";")
            self.row, self.col = int(row or 1) - 1, int(col or 1) - 1
        elif final == "J":                      # ED: to the end of the screen
            self._erase_below()
        elif final == "K":                      # EL: to the end of the row
            self._erase_right()
        elif final == "m":                       # SGR
            self.sgr = "" if params in ("", "0") else match.group(0)
        elif final == "h" or final == "l":       # DEC private modes we set
            if params not in ("?2026", "?25", "?7", "?2004", "?1049"):
                self.unknown.append(match.group(0))
        else:
            self.unknown.append(match.group(0))
        return match.end()

    def text(self):
        return "\n".join("".join(row).rstrip() for row in self.cells)
```

**Spec coverage.** Every numbered Phase-1 item of `03-tui-port.md` §"MVS ladder" maps to a task (table under §Scope), and every Phase-1 scenario of `06-qa-harness.md` maps to Task 19's table plus a cargo-level test in Tasks 2-18. **Type continuity.** `Geometry`, `Band`, `RenderRequest`, `Transcript`, `Append`, `wrap::Row`, `Decoder`/`Input`/`Action`, `Editor`, `UiEvent`/`TurnControl`/`TurnWork`, `Cancellation`, `Worker`, `Palette`, `Hint`, `Panel`, `Paste` are each defined in one task and consumed only by later ones. The two seams that cross into existing code — `output::EventSink` for `UiEventSink` and `permission::ApprovalPrompter` for `TuiPrompter` — are implemented against the signatures as they exist today (`src/output.rs:968-972`, `src/permission/policy.rs:340-342`), which is what forces `park_on` rather than an `async` refactor of a module this plan may not touch.

**Boundary.** No task edits `src/gateway/`, `src/llmux/`, or provider selection. `app::build_provider` is called unchanged; `/model` keeps `interactive::apply_model`'s semantics; the four edits outside `src/tui/` are enumerated in the Global Constraints and are visibility widenings plus a five-line route in `main.rs`.

**Findings fixed during this review, listed because a plan that hides its own repairs teaches nothing:**

1. *`blocking_send` would have been the obvious bridge and would have panicked.* The spec forbids it and offers `blocking_send` for a "genuinely synchronous producer" in the same breath — which is only correct off-runtime. Task 10's `park_on` replaces both, and the deviation is stated in the Global Constraints instead of being buried in a module.
2. *`app::permission_session` attaches `TtyPrompter`, which reads stdin.* Reusing it in the worker would have put a second reader on the descriptor the UI thread polls — a bug that would look like "keys sometimes vanish" and would have survived every unit test. Tasks 11 and 17 build the session locally and say why.
3. *The restoration matrix cannot be read on macOS through a controlling terminal.* A session leader's terminal is revoked when it exits on BSD kernels, so a post-exit `tcgetattr` measures a pristine device. Every restore case uses `Session::spawn_without_taking_the_terminal`, which the existing harness already provides for exactly this reason; the interaction cases keep the controlling terminal.
4. *`pipe2` is not portable.* macOS has no such call, so Task 3 uses `pipe()` plus `fcntl` for `O_NONBLOCK` and `FD_CLOEXEC` on both ends rather than `pipe_with`.
5. *`SA_RESTART` would have hidden the resume.* Installing handlers with `libc::signal` (BSD semantics) sets it, and a parked `read`/`poll` would then never return to observe the resume flag. Task 3 installs with `sigaction` and `sa_flags = 0`, and Task 6's loop treats `EINTR` as a normal wakeup.
6. *`tokio-util` is not the only new dependency.* The spec calls it "the one new dependency" in the runtime-topology section, but its own §"Crate strategy" requires `unicode-segmentation` and `unicode-width`, and no portable `sigaction` exists in `rustix` 1.1.4 (`runtime` is Linux-only and internal), so `libc` becomes direct — it is already in `Cargo.lock` at 0.2.189. All four are named in the Tech Stack with their reasons instead of being introduced quietly in a task.
7. *`pyte` is not on the CI images.* `06-qa-harness.md` names it as "the obvious choice"; installing it would put a network fetch inside a suite whose rule is no-network. Task 19 writes a bounded emulator that additionally **fails on any sequence it does not know**, which pins the emitted subset as a contract.
8. *`check-no-stubs.sh` would have failed on the word "placeholder".* The pasted-block collapse is the one Phase-1 feature whose natural vocabulary is a forbidden literal; Task 18 names it `Pasted`/`summary`/`collapse` and the trap is recorded in the Global Constraints.
9. *A half-built TUI would otherwise have been advertised.* The ledger row is edited by the task that made each sentence true, and Task 11 explicitly writes down that `ask` mode has no approval channel until Task 17 removes that sentence — the one place in this plan where the honest ledger entry is an admission of a gap.
10. *`window_size` had been placed in `layout.rs` while Task 5 needed it first.* It belongs to `term.rs` (Task 2), which is where a terminal query lives; `layout::solve` takes rows and columns as arguments and stays pure, which is also what makes its unit tests possible.
11. *`Band`'s interface listed only `commit`/`append_document` while the tests call `render`/`render_append`.* Both pairs exist: `render`/`render_append` build the bytes and are what the unit tests assert on; `commit`/`append_document` write them in one `write_all`. Keeping the byte-building pure is what makes a frame assertable without a terminal.
12. *The fault injector belongs in its own module.* Task 4 creates `src/tui/panic.rs` for the hook and `src/tui/fault.rs` for `Fault`/`injected`, so that Task 11's `WorkerTurn` and `SlowUi` faults do not have to grow inside a file about panics.

**Known risks, pre-registered rather than discovered later.** Full-band repaint without a cell diff makes per-frame bytes large over tmux and ssh — no flicker, because `?2026` handles that, but bandwidth becomes the complaint, and Phase-2 item 11 is the answer if it does. `rustix`'s own documentation warns that on macOS `poll` does not work on `/dev/tty` file descriptors (`src/event/poll.rs:12-13`); a controlling pty slave is not that case, but if the loop ever misbehaves there, `rustix::event::select` is the documented fallback and the change is local to `event_loop.rs`. And the property this whole phase inverts: "nothing to restore" becomes "a restore path that must be right on every exit", which is why Task 19's scenario 3 runs every earlier phase's restoration cases again, on a release binary, on both platforms.
